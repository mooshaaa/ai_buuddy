# AI-buddy: помощник стажёра (база прототипа)

Веб-интерфейс с чатом и панелью этапов адаптации. Бэкенд на FastAPI, фронтенд на React + TypeScript, PostgreSQL.
Сейчас «мозг» бота — заглушка без LLM, поэтому всё работает без ключей. Данные синтетические.

## Запуск

```bash
# .env не обязателен: по умолчанию работает заглушка. Для своей модели: cp .env.example .env
docker compose up --build
```

- Интерфейс: http://localhost:5173
- API и документация: http://localhost:8000/docs

Без Docker: `cd backend && pip install -r requirements.txt && uvicorn app.main:app --reload` (SQLite, файл `app.db`), затем `cd frontend && npm install && npm run dev`.

## Что умеет сейчас

- Выбор пользователя (стажёр или наставник) в шапке, права зависят от роли.
- Сценарий «отгул»: «Хочу отгул 20 ноября» → карточка действия → «Подтвердить» → мок-сервис отсутствий возвращает номер заявки → статус сохраняется в БД.
- Этапы адаптации из чек-листа: прогресс, следующий шаг, отметка выполнения.
- Ответы на вопросы по мини-базе знаний (доступы, 1:1, экватор, защита данных).
- Показательный отказ по правам: стажёр просит «прогресс стажёра» и получает отказ, наставник видит данные.

## Структура

```
backend/app/
  main.py      эндпоинты
  agent.py     оркестратор: понять запрос → проверить права → вызвать инструмент → собрать блоки
  llm/         интерфейс LLMProvider и заглушка (сюда подключается реальная модель)
  policy.py    проверка прав по ролям (единая точка)
  tools.py     мок корпоративных сервисов (позже MCP-серверы)
  kb.py        мини-база знаний
  seed.py      синтетические данные из чек-листа
  schemas.py   контракт блоков ответа
backend/tests/ тесты (pytest)
frontend/src/  App, Chat, Blocks (рендер блоков), StagesPanel
```

## Контракт ответа агента

`POST /api/chat` с `{ "user_id": "intern_1", "message": "..." }` возвращает `{ "blocks": [...] }`.
Типы блоков: `text`, `error`, `action_card` (поля `action_id`, `title`, `params`, `status`, `result`).
Новый тип блока: добавить модель в `schemas.py`, тип в `frontend/src/types.ts`, ветку в `Blocks.tsx`.

Остальные эндпоинты: `GET /api/users`, `GET /api/stages?user_id=`, `POST /api/stages/{id}/toggle`,
`POST /api/actions/{id}/confirm`, `POST /api/actions/{id}/cancel`.

## Как подключить реальную модель

1. Создать класс с методом `parse(user, message) -> Intent` в `backend/app/llm/` (модель извлекает намерение и параметры, вызов инструментов остаётся в коде агента).
2. Добавить ветку в `llm/__init__.py` и переменные в `.env` (`LLM_PROVIDER`, `LLM_MODEL`, `LLM_API_KEY`).
3. Сбой модели уже обрабатывается: агент возвращает блок `error`, интерфейс не зависает.
