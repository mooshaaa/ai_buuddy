# 04. Права доступа

## Цель
Каждое действие выполняется только если роль пользователя на него уполномочена. Проверка происходит на сервере, а не в интерфейсе.

## Матрица прав (`backend/app/policy.py`)
| Роль | Инструменты |
|---|---|
| Стажёр (`intern`) | `create_absence` |
| Наставник (`mentor`) | `create_absence`, `view_team_progress` |

## Правила
1. Роль берётся из таблицы `users` по `user_id`, а не из текста сообщения.
2. Единая точка проверки: функция `assert_allowed` вызывается в `tools.execute` перед любым инструментом.
3. Агент проверяет права ещё до создания карточки действия (`create_absence`).
4. Отказ формулируется понятно: стажёр, запросивший прогресс, получает объяснение, что функция доступна только наставнику.
5. Действие принадлежит создавшему его пользователю: подтвердить или отменить чужое действие нельзя (HTTP 403).
6. Записи базы знаний «только для наставника» не попадают в контекст модели стажёра (см. 02).
7. Неизвестный `user_id` возвращает 404.

## Границы
Аутентификации нет: вход без пароля, пользователь выбирается в интерфейсе (прототип). В продакшене роль должна определяться по сессии или токену.

## Критерии приёмки и трассировка
| Критерий | Тест |
|---|---|
| Стажёр не получает прогресс стажёров, видит отказ | `test_api::test_intern_denied_team_progress` |
| Наставник получает прогресс | `test_api::test_mentor_sees_team_progress` |
| Чужое действие подтвердить нельзя | `test_api::test_cannot_confirm_foreign_action` |
| Записи для наставника скрыты от стажёра | `test_kb::test_role_filter`, `test_stub_does_not_leak_mentor_only_entry_to_intern` |
| История одного пользователя недоступна другому | `test_history::test_history_is_per_user` |
| Неизвестный пользователь отвергается | `test_api::test_unknown_user`, `test_history::test_reset_unknown_user` |
