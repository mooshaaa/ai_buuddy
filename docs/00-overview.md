# 00. Обзор системы

## Цель
AI-buddy помогает стажёру пройти адаптацию без постоянных обращений к наставнику: отвечает на вопросы по базе знаний,
оформляет отгул через корпоративный сервис, показывает этапы чек-листа. Наставник видит прогресс стажёров.

## Роли
- **Стажёр (`intern`)**: задаёт вопросы, оформляет отгул, видит свои этапы.
- **Наставник (`mentor`)**: всё то же, плюс прогресс стажёров и записи базы знаний для наставников.

## Поток обработки запроса (`POST /api/chat`)
1. Загрузить последние сообщения пользователя (память диалога).
2. Модель (или заглушка) определяет намерение и параметры: `create_absence`, `show_stages`, `team_progress`, `faq`, иное.
3. Агент проверяет права и вызывает инструмент или отвечает по базе знаний.
4. Ответ собирается списком блоков: `text`, `error`, `action_card`, `source`.
5. Пара «вопрос и ответ» сохраняется в историю.

## Правила
1. Модель только извлекает намерение и параметры. Инструменты вызывает код агента после проверки прав.
2. Действие с побочным эффектом выполняется только после подтверждения пользователем (см. 05).
3. Любой сбой модели не должен ломать интерфейс: порядок отката: основная модель, запасная модель, заглушка на правилах.
4. Если и обработка запроса, и откат не удались, пользователь получает блок `error` с понятным текстом.
5. Запросы обрабатываются синхронными эндпоинтами FastAPI в пуле потоков, поэтому долгий вызов модели не блокирует сервер.
6. Пока идёт запрос, интерфейс показывает состояние ожидания и блокирует повторную отправку.

## Память диалога
- История хранится на бэкенде в таблице `messages` и привязана к `user_id`.
- Модель получает последние **8** сообщений, каждое обрезается до **1 500** символов, как данные, а не как инструкции.
- Блоки `error` в контекст не попадают; карточки действий и источники передаются кратким текстом.
- После перезагрузки страницы диалог восстанавливается (последние 50 сообщений), карточки показываются с актуальным статусом.
- «Новый диалог» (`POST /api/history/reset`) помечает сообщения `archived=true`: в контекст и интерфейс они не попадают, но остаются в БД.

## Границы
Вход без пароля (прототип): `user_id` передаётся в запросах. Данные и сервисы синтетические, сервис отсутствий мок.

## Критерии приёмки и трассировка
| Критерий | Тест |
|---|---|
| Сообщения сохраняются и восстанавливаются по порядку | `test_history::test_messages_are_saved_and_restored_in_order` |
| История привязана к пользователю | `test_history::test_history_is_per_user` |
| Модель получает предыдущие реплики | `test_history::test_provider_receives_previous_turns` |
| Контекст ограничен 8 сообщениями и обрезан | `test_history::test_context_limited_to_last_8_and_truncated` |
| «Новый диалог» архивирует, но не удаляет | `test_history::test_reset_archives_but_keeps_rows` |
| Ошибки не попадают в контекст | `test_history::test_error_only_reply_not_in_context` |
| Карточка после перезагрузки с текущим статусом | `test_history::test_restored_card_shows_current_status` |
| История передаётся модели как данные | `test_llm::test_history_goes_into_prompt_as_data` |
| При сбое основной модели срабатывает заглушка | `test_llm::test_fallback_provider_uses_stub_on_failure` |
| При лимите запросов включается запасная модель | `test_llm::test_fallback_model_on_rate_limit` |
| При сбое всех моделей пользователь получает понятную ошибку | `test_kb::test_agent_answer_error_is_graceful`, `test_llm::test_all_models_fail_raises` |
| Режим модели виден в `/health` | `test_api::test_health` |
| Неизвестное значение намерения от модели отвергается | `test_llm::test_unknown_intent_value_is_rejected` |
| Отладка выключена по умолчанию | `test_debug::test_debug_off_hides_info_and_events` |
