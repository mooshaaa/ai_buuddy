# 05. Действие через сервис: заявка на отгул

## Цель
Стажёр оформляет отгул диалогом. Система вызывает корпоративный сервис отсутствий (сейчас мок), сохраняет результат и показывает номер заявки.

## Поток
1. Пользователь: «Хочу отгул в понедельник».
2. Модель извлекает намерение `create_absence` и параметры (`date`, `kind`).
3. Если даты нет, бот спрашивает: «На какую дату оформить отгул?».
4. Агент проверяет права и создаёт действие (`actions`) со статусом `needs_confirmation`, показывает карточку.
5. Пользователь нажимает «Подтвердить» (`POST /api/actions/{id}/confirm`) или «Отменить» (`.../cancel`).
6. После подтверждения вызывается сервис: запись в таблицу `absences`, возвращается `request_id` вида `ABS-0001`, статус действия `done`.
7. Результат сохранён в БД и показан в карточке.

## Параметры
- `date`: дата в формате `ГГГГ-ММ-ДД`. Понимаются «завтра», «послезавтра», «в понедельник», «20 ноября».
- `kind`: `day_off` (отгул) или `vacation` (отпуск).

## Статусы действия
`needs_confirmation` → `done` (подтверждено) или `rejected` (отменено). Повторное подтверждение уже выполненного действия возвращает карточку без повторного вызова сервиса.

## Правила
1. Без явного подтверждения пользователя сервис не вызывается.
2. Некорректная дата или тип отсутствия отклоняются (HTTP 400).
3. Если модель вернула некорректную дату, она восстанавливается из текста сообщения.
4. Уточнение в следующем сообщении («20 ноября» в ответ на вопрос бота) понимается как продолжение сценария. Одинокая дата вне такого вопроса заявкой не становится.
5. Права проверяются дважды: до создания карточки и при вызове сервиса (см. 04).

## Границы
Нет согласования заявки наставником и проверки остатка отгулов. Сервис отсутствий мок. Подключение реального API или MCP-сервера выполняется заменой реализации в `tools.py`, остальные части не меняются.

## Критерии приёмки и трассировка
| Критерий | Тест |
|---|---|
| Запрос → карточка → подтверждение → номер заявки | `test_api::test_absence_flow` |
| Без даты бот спрашивает дату | `test_api::test_absence_asks_for_date` |
| Отмена не вызывает сервис | `test_api::test_cancel_action` |
| Чужое действие подтвердить нельзя | `test_api::test_cannot_confirm_foreign_action` |
| Разбор дат («завтра», «20 ноября», день недели) | `test_api::test_parse_date`, `test_llm::test_prompt_contains_weekday_calendar`, `test_weekday_recovered_when_model_gives_no_date` |
| Некорректная дата от модели восстанавливается | `test_llm::test_bad_date_from_model_is_recovered_from_message` |
| Модель без даты оставляет поле пустым | `test_llm::test_absence_without_date_stays_none` |
| Ответ на вопрос бота о дате продолжает сценарий | `test_history::test_date_followup_after_bot_asks` |
| Отпуск сохраняется как `vacation` при уточнении | `test_history::test_vacation_followup_keeps_kind` |
| Одинокая дата не создаёт заявку | `test_history::test_plain_date_without_question_is_not_absence` |
| Карточка в истории показывает актуальный статус | `test_history::test_restored_card_shows_current_status` |
